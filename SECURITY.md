# Security Policy

## ⚖️ Ethical & Authorized Use Only

**VulnScanner** is designed and maintained strictly for authorized security assessments, penetration tests, and defensive audits. Unauthorized scanning or testing of network infrastructure and web applications without explicit prior written authorization is illegal.

---

## 🛡️ Supported Versions

We actively provide security patches and dependency updates for the following versions:

| Version | Supported          | Python Compatibility |
| ------- | ------------------ | -------------------- |
| 1.1.x   | :white_check_mark: | 3.10, 3.11, 3.12, 3.13 |
| 1.0.x   | :x:                | Deprecated           |

---

## 🚨 Reporting a Vulnerability

If you discover a security vulnerability or weakness within VulnScanner itself (e.g. insecure subprocess execution, unsafe deserialization, or credential leakage), please report it responsibly:

1. **Do NOT open a public GitHub Issue** to report security vulnerabilities.
2. Email the maintainers directly or use [GitHub Private Vulnerability Reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-communicating/privately-reporting-a-security-vulnerability).
3. Include:
   - Module and line number affected
   - Detailed proof of concept (PoC) or reproduction steps
   - Potential impact and CVSS assessment
   - Suggested remediation or patch if available

---

## ⏱️ Response Timeline

- **Initial Acknowledgment**: Within 48 hours of receipt.
- **Triage & Assessment**: Within 5 business days.
- **Fix & Patch Release**: Typically within 14 business days, coordinated with private disclosure.
